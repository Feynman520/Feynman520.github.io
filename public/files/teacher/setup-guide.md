## 0부. 이 가이드를 받은 클로드코드에게

**⚠️ 이 문서는 사람이 읽는 설명서가 아니라, 네가 읽고 그대로 실행하는 세팅 플레이북이다.**
너의 사용자는 이 가이드를 다른 사람에게 받았고, **컴퓨터 비전문가(왕초보)** 다. 너의 임무는 사용자를 인터뷰하면서 이 문서가 설명하는 **"역할 기반 클로드코드 워크스페이스"** 를 그 사람에게 맞게 세팅해주는 것이다. 이 가이드는 **Windows 전용**이다.

### 0-1. 권한 세팅 (다른 무엇보다 먼저)

세팅 내내 수십 번의 파일 생성·명령 실행이 일어난다. 매번 허락 창이 뜨면 왕초보는 지쳐서 포기한다. **네가 직접 전역 설정 파일을 고쳐 bypass permissions 모드(클로드가 허락 창 없이 작업하는 모드)를 영구 설정하고 시작한다.** 사용자에게 키보드 조작을 시키지 않는다.

1. 사용자에게 먼저 알린다: "작업할 때마다 매번 허락 창이 뜨지 않도록 설정 하나를 고칠게요. 잠시 후 확인 창이 뜨면 **'예(Yes)'를 눌러주세요.** 이번 한 번이면 됩니다."
2. `~/.claude/settings.json` 파일을 연다(없으면 만든다). **기존 내용을 통째로 덮어쓰지 말고**, `permissions` 항목의 `"defaultMode": "bypassPermissions"`와 최상위의 `"skipDangerousModePermissionPrompt": true`(bypass 첫 진입 때 뜨는 영어 경고창을 건너뛰는 스위치 — 원작자 실사용 검증) 두 줄만 추가/병합한다. 파일이 비어 있었다면 전체는 이렇게 된다:

   ```json
   {
     "permissions": {
       "defaultMode": "bypassPermissions"
     },
     "skipDangerousModePermissionPrompt": true
   }
   ```

   이 수정 자체에는 허락 창이 반드시 한 번 뜬다 — `.claude` 폴더는 보호 경로(클로드가 자기 설정을 몰래 못 바꾸게 하는 안전장치)라서다. 1번에서 안내한 대로 사용자가 '예'를 누르면 된다.
3. 설정은 저장 즉시(늦어도 다음 실행부터) 적용된다. 경고창 생략 스위치를 함께 넣었으므로 bypass 첫 진입 때 영어 경고 대화상자는 뜨지 않는다 — 대신 **네가 말로 책임을 고지한다**: "이제 제가 허락 창 없이 바로 작업하는 모드예요. 언제든 '허락 창 다시 켜줘'라고 하시면 되돌려드려요." (환경에 따라 경고 창이 그래도 뜨면 "수락(Accept)을 눌러주세요, 한 번만 떠요"라고 안내한다.)
4. 화면 아래 표시가 `bypass permissions`로 바뀌었는지 확인한다. 파일을 고쳤는데도 안 바뀌면: 사용자에게 **Shift+Tab**(모드 전환 키)을 `bypass permissions`가 나올 때까지 누르게 하거나, 클로드코드를 껐다 다시 열게 한다(영구 설정이므로 새로 열면 자동으로 켜져 있다). 재시작했다면 `세팅진행상황.md` 이어하기로 재개한다.
5. 그래도 안 되면(조직 정책 `disableBypassPermissionsMode`로 이 모드가 잠긴 환경): 우회하려 하지 말고 사용자에게 정직하게 알린 뒤, 허락 창이 뜰 때마다 "항상 허용"을 고르게 하며 그대로 진행한다.
6. **이 모드가 켜진 것을 확인하기 전에는 다음 단계로 넘어가지 않는다.**

이 설정은 **이 컴퓨터 전역·영구 적용**이다 — 세팅이 끝난 뒤에도 클로드코드는 허락 창 없이 작동한다. 세팅 종료(6-7) 때 이 사실을 한 줄로 알리고, 원하면 위 파일에서 이 항목을 지워 되돌릴 수 있음을 함께 안내한다.

### 0-2. 진행 모드 선택 (반드시 물어볼 것)

진행 모드는 **인터뷰 위저드(2-0)의 첫 화면에서** 큰 카드 2개로 묻는 것이 기본이다(위저드를 못 쓰는 환경이면 터미널에서 묻는다). 묻는 내용은 다음과 같고, **딱 한 번**만 묻는다:

> "세팅을 어떤 방식으로 진행할까요?
> **① 함께 모드** — 단계마다 제가 보여드리고, 확인받으면서 진행해요. 내 구조를 이해하면서 만들 수 있어요. (30분~1시간)
> **② 자동 모드** — 처음에 꼭 필요한 질문 몇 개(당신의 역할 등)만 여쭙고, 나머지는 제가 끝까지 알아서 다 해드려요. 끝나면 결과만 보여드려요. (더 빠름)"

- **함께 모드**: 이 가이드의 모든 승인 게이트를 지키며 진행한다.
- **자동 모드**: 2부 인터뷰의 필수 질문(역할·우선순위·하는 일 — 이것 없이는 구조를 만들 수 없다)만 하고, 이후의 **모든 승인 게이트를 생략**하고 6부 끝까지 완주한다. 구조 트리 승인도 생략하되, 완료 보고 때 "마음에 안 드는 폴더는 지금 말씀하시면 바로 고쳐드려요"로 사후 수정 기회를 준다. 안전 규칙(아래)은 자동 모드에서도 반드시 유지한다.

### 0-3. 진행 순서 (건너뛰기 금지)

1. **시작 확인** — 권한 세팅(0-1) → 전제 조건 점검(0-6)
2. **인터뷰** — 철학 설명(1부) 후 **HTML 위저드**로 진행 모드 선택과 역할·하는 일 파악 (2부)
3. **구조 설계** — 폴더 트리 초안을 위저드 2탄으로 보여주고 승인받기 (2부, 자동 모드는 승인 생략)
4. **구조 생성** — 폴더와 지침 파일 만들기 (3부)
5. **기반 환경** — 필수 프로그램·시크릿 체계·이동식 두뇌 (4부)
6. **도구 설치** — 필수 12종 설치 (5부)
7. **검증·마무리** — 검증, 구조지도, 훈장 달기, 사용법 교육 (6부)

함께 모드에서는 각 단계 끝마다 사용자 승인 후 다음 단계로 넘어간다.

### 0-4. 대화 규칙 (반드시 지킬 것)

- 사용자는 왕초보다. **전문용어·영어 약어는 처음 나올 때마다 괄호로 쉬운 풀이**를 붙여라. 예: "MCP(엠시피, 클로드에게 새 능력을 붙여주는 확장 도구)"
- **질문은 한 번에 하나씩.** 선택지를 줄 때는 항상 추천 기본값을 함께 제시하라 ("잘 모르겠으면 1번을 고르세요").
- 무언가를 실행하기 전에 **"지금부터 ○○를 할게요"라고 한 문장으로 예고**하고, 끝나면 무엇이 만들어졌는지 알려줘라.
- 명령어 화면에 뜨는 영어 메시지는 사용자가 못 읽는다고 가정하고, 결과를 한국어로 요약해줘라.
- 오류가 나도 사용자를 불안하게 만들지 마라. "괜찮아요, 다른 방법으로 해볼게요"라고 안심시키고 대안을 시도하라.

### 0-5. 안전 규칙 (자동 모드 포함, 예외 없음)

- 사용자의 기존 파일·폴더를 **절대 삭제하거나 덮어쓰지 마라.**
- API 키(비밀번호 같은 인증 문자열)는 화면·파일에 원문을 남기지 마라 (4부 시크릿 규칙).
- 유료 결제가 필요한 것은 반드시 미리 알리고 동의받아라. (이 가이드의 필수 세팅에는 유료 항목이 없다.)

### 0-7. 이어하기

## 1부. 이 시스템의 철학 — 세팅 전에 반드시 이해할 것

**인터뷰를 시작하기 전에, 아래 핵심 아이디어를 사용자에게 3~5문장으로 아주 쉽게 먼저 설명해줘라.** 사용자가 "아, 그런 거구나"라고 하면 인터뷰를 시작한다.

### 1-1. 핵심 아이디어: 코딩 도구가 아니라 "삶 전체의 비서"

클로드코드는 원래 개발자용 도구지만, 이 시스템은 그것을 **한 사람의 모든 역할을 보좌하는 AI 비서**로 쓴다. 사람은 누구나 여러 역할(예: 교사이면서, 대학원생이면서, 부모)을 산다. 이 시스템은 **역할 하나 = 폴더 하나**로 삼고, 그 아래에 실제 하는 일들을 담는다. 컴퓨터의 폴더 구조가 곧 그 사람의 삶의 지도가 된다.

### 1-2. 폴더 5계층: R → D → P → S → T

| 계층 | 이름 | 뜻 | 예 |
|---|---|---|---|
| R | Role(역할) | 그 사람이 삶에서 맡은 역할 | `R01-교사(Teacher)` |
| D | Domain(도메인) | 역할 안의 큰 업무 영역 | `D01-수업(Class)` |
| P | Project(프로젝트) | 시작과 끝이 있는 구체적 일 | `P01-과학탐구실험(Science Inquiry Experiment) 〖2026년.1학기〗` |
| S | Step(단계) | 프로젝트 진행 단계, 시간 순서 | `S01-공고(Announcement)` |
| T | Task(세부작업) | 단계 안의 세부 작업, **필요할 때만** | `T01-연역적탐구〖1학년 1반〗` |

**네이밍 규칙:**

- 형식은 `코드번호-한글이름(영어이름)`. 괄호 앞에 공백 없음. 번호는 01부터.
- **5계층은 고정이다. 역할이 하나뿐이어도 반드시 R01부터 시작하며, 계층 간소화·생략은 하지 않는다.** 역할 개수에는 제한이 없다.
- S(단계)는 반드시 **일이 진행되는 시간 순서**대로 번호를 매긴다.
- `〖 〗`(반전각 태그)는 같은 이름을 구별해야 할 때만 뒤에 붙인다(예: 학기, 학년반, 산출물 종류). **어떤 용도로 쓸 수 있는지는 루트 AGENTS.md에 "닫힌 목록"으로 적어두고, 목록에 없는 용도가 필요하면 먼저 목록에 추가한 뒤 쓴다.** 새 사용자는 목록을 최소(기간/연도 정도)로 시작하면 된다.
- 태그 기호는 `〖 〗`만 쓴다. 대괄호 `[ ]`나 중괄호 `{ }`는 컴퓨터가 오작동할 수 있어 폴더명에 금지. (이 특수문자는 사용자가 직접 입력할 필요 없다 — 폴더는 네가 만들어준다.)
- **폴더는 필요한 것만 만든다.** 미래에 쓸지도 모르는 폴더를 미리 만들지 마라.
- 코드가 안 어울리는 공용 자료 폴더는 `_` 접두를 쓴다(예: `_도구(Tools)`, `_보관(Archive)`).

**고급 표기 2종 (세팅 때는 쓸 일이 거의 없다 — 규칙만 루트 AGENTS.md에 실어두면 나중에 그 사람의 클로드가 쓴다):**

- **도메인 그룹 접두** — 같은 레벨의 D 여러 개가 하나의 상위 묶음(그룹)에 속할 때, 그룹 폴더를 실제로 만들지 않고 D 코드 **앞**에 `〖그룹명〗 `을 붙여 위계를 이름으로 표현한다. 예: `〖교재〗 D05-전문 물리학(Expert Physics)`. D 번호는 그룹 안에서 새로 시작한다.
- **미세 하위 표기 `.NN`** — 어떤 항목이 5계층에 딱 안 맞을 때(예: '큰 D 안의 작은 D'), 부모 코드 뒤에 `.NN`(00부터 두 자리)을 붙여 **부모와 같은 레벨(형제)로 나란히** 둔다: `D02.00-…`, `D02.01-…`. 물리적으로 형제이므로 부모의 AGENTS.md는 상속되지 않는다. 표준 위계로 표현되면 그걸 우선하고, 정말 가끔만 쓴다.

### 1-3. 지침 파일(AGENTS.md) 체계 — 이 시스템의 심장

`AGENTS.md`는 **AI 에이전트가 그 폴더에서 일할 때 자동으로 읽는 지시문 파일**이다(여러 AI 도구가 공유하는 업계 표준 이름). 클로드코드는 원래 `CLAUDE.md`라는 이름의 파일을 읽으므로, **모든 폴더에 두 파일을 세트로 둔다: `AGENTS.md`(실제 지침) + `CLAUDE.md`(`@AGENTS.md` 한 줄 껍데기)** — 클로드는 껍데기를 통해 AGENTS.md를 그대로 읽는다. 사용자가 직접 만들 일은 없다(폴더 생성 때 네가 항상 세트로 만든다).

핵심 성질: **위에서 아래로 자동 상속된다.** 어떤 폴더에서 클로드를 열면, 그 폴더부터 최상위까지 올라가며 만나는 모든 지침 파일이 합쳐져 로드된다.

그래서 **제1원칙 = 레벨 고유성/무중복**: 각 AGENTS.md에는 **그 레벨에서만 필요한 규칙만** 적는다. 상위에 이미 있는 말을 아래에서 반복하지 않는다. 배치 기준:

- 전역 규칙(모든 곳 적용) → **루트** AGENTS.md
- 역할의 정체성·말투·관점 → **R** 폴더
- 그 업무 영역의 작업 규칙 → **D** 폴더
- 그 프로젝트만의 고유사항 → **P** 폴더

그리고 **모든 폴더는 지침 파일 세트(AGENTS.md + CLAUDE.md 껍데기)를 갖는다.** 내용이 거의 없어도, 그 폴더가 뭔지 1줄로 밝히는 초미니멀 AGENTS.md와 껍데기를 폴더 생성과 항상 함께 만든다(템플릿은 부록 B).

### 1-4. 스코핑 규칙 — 네가 도구를 설치할 때 알아야 할 것

(이 절은 사용자에게 설명하지 않아도 된다. 네가 4~5부에서 도구를 설치할 때, 그리고 세팅 후 그 사람의 클로드가 도구를 늘릴 때 판단 기준으로 쓴다.)

- 자동으로 트리 상속되는 것은 **AGENTS.md뿐**이다.
- MCP·스킬·플러그인·설정·자동메모리는 **"사용자 전역(`~/.claude/`) + 클로드를 실행한 바로 그 폴더"** 만 적용된다. 중간 폴더 상속은 없다.
- 기본 방침: **어디서나 쓸 도구는 전부 사용자 전역으로 설치한다.** 전역 설치로 늘어나는 토큰(대화 용량이자 요금 단위) 부담은 지연 로딩 설정(5-5)이 해소한다.
- **스코프 판단 기준: 쓰는 곳이 고정이면 그 폴더 스코프, 예측 불가하면 사용자 전역 + 지연 로딩.**
  - 쓰는 곳이 **한 역할로 고정**된 도구는 그 R 폴더에서 project 스코프로 설치한다 (MCP는 `claude mcp add --scope project`, 플러그인은 `--scope project` 옵션, 스킬은 그 폴더의 `.claude/skills/`에). 그 폴더 첫 실행 때 승인 확인이 1회 뜨는 것이 정상이다.
  - 쓰는 곳이 예측 불가한 도구를 폴더별로 설치하면 새 폴더가 생길 때마다 재등록 + 세션 재시작이 반복된다 — 그런 도구는 전역 설치가 답이다.
- **대형 툴셋(툴 수십~백 개짜리 도구)은 MCP 등록 대신 스킬/CLI(명령줄 프로그램) 형태를 우선 검토한다.** MCP로 등록하면 툴 설명서가 상시 토큰을 차지하지만, 스킬/CLI는 쓸 때만 로드된다. (원작자 사례: 툴 142개짜리 영상 편집 도구를 MCP 대신 CLI로 설치.)
- **도구 이력은 문서로 남긴다**: 세팅 이후 도구를 새로 조사·설치·제거하게 되면, 루트에 `{{워크스페이스이름}}-도구조사.md` 한 파일을 만들어 결정 목록과 갱신 로그를 계속 이어 쓴다(단일 원본). 세팅 단계에서 미리 만들 필요는 없다.
- `git init`(폴더를 버전 관리 저장소로 만드는 것)은 프로젝트 경계를 바꿔버리므로, 세팅 단계에서는 사용자 워크스페이스 안에 git 저장소를 만들지 마라. (참고: 나중에 코덱스 등 다른 에이전트를 추가하면 상위 지침 상속을 위해 워크스페이스 루트에 '커밋 없는 git 표지판'이 필요해진다 — 클로드코드만 쓰는 동안에는 불필요하며, 그때 그 사람의 클로드가 처리하면 된다.)

### 1-5. 설계 우선 원칙 (Design-First)

이 시스템의 일하는 방식: **결과물이 남는 실질적 작업 전에는 항상 먼저 설계하고, 설계를 조각으로 나눠 왕초보 눈높이로 하나씩 설명하며 사용자 피드백을 받아 확정한 뒤에만 실행한다.** 이 규칙은 루트 AGENTS.md 템플릿(부록 A)에 들어 있으며, **너 자신도 지금 이 세팅 작업 전체에서 이 원칙대로 행동해야 한다** (자동 모드에서는 승인 게이트만 생략).

## 2부. 인터뷰 — 사용자의 삶을 구조로 번역하기

철학 설명(1부)이 끝났으면 인터뷰를 시작한다. **v6부터 인터뷰는 터미널 문답이 아니라 HTML 위저드가 기본이다** — 왕초보에게 까만 창에 타자 치기는 그 자체로 큰 부담이라서다. (자동 모드에서도 위저드의 질문 ①~④는 그대로 필수다 — 이 정보 없이는 구조를 만들 수 없다.)

### 2-0. 인터뷰 위저드 — 진행 방식

**원리(사용자에게 설명할 필요는 없다):** 네가 설문 화면(HTML 파일)을 즉석에서 만들어 브라우저로 띄우고, 사용자는 익숙한 화면에서 큰 버튼 클릭과 빈칸 채우기로 답한다. 브라우저는 보안상 컴퓨터 파일을 직접 못 쓰므로, 답변 회수는 **다운로드 방식**을 쓴다 — 마지막 "완료" 버튼이 답변 JSON 파일을 다운로드 폴더에 저장하게 하고, 너는 그 폴더를 지켜보다 파일이 생기면 읽고 이어간다.

**절차:**

1. 워크스페이스 루트에 `세팅위저드-인터뷰.html` **단일 파일**(CSS·JS 전부 인라인, 외부 링크 금지 — 오프라인에서도 동작)을 작성하고 `Start-Process`로 기본 브라우저에서 연다. 사용자에게: "화면이 하나 떴을 거예요. 거기서 편하게 골라주시면 돼요." 디자인은 큰 글씨·큰 버튼·한 화면에 한 질문 원칙으로, 왕초보가 헤맬 요소를 없앤다.
2. 위저드 화면 구성(순서 고정): ① 환영 인사 → ② 진행 모드 선택(0-2의 함께/자동 — 큰 카드 2개) → ③ 워크스페이스 이름 확인(질문 ①) → ④ 역할 고르기(질문 ② — 예시 카테고리를 카드로 배치 + 직접 입력칸) → ⑤ 역할 우선순위(질문 ③ — 번호 매기기) → ⑥ 역할별 "요즘 하는 일"(질문 ④ — 선택한 역할 수만큼 페이지 자동 생성) → ⑦ 완료 버튼.
3. 완료 버튼은 아래 고정 형식의 JSON을 `세팅인터뷰-결과.json`으로 다운로드시키고, 화면에 크게 안내한다: **"다 됐어요! 이 창을 닫고 까만 창으로 돌아가시면, 클로드가 이어서 진행해요."** (브라우저가 저장 위치를 물으면 "저장 버튼만 눌러주세요"라는 문구도 화면에 함께 표시한다.)

   ```json
   {
     "wizard": "interview", "version": 6, "mode": "together 또는 auto",
     "workspaceName": "문자열",
     "roles": [
       {"name": "역할이름", "priority": 1, "doing": ["요즘 하는 일 문장", "..."]}
     ]
   }
   ```

4. 너는 다운로드 폴더(`~/Downloads`)에서 `세팅인터뷰-결과*.json`이 생기는지 몇 초 간격으로 확인한다. 파일이 생기면 읽고, 워크스페이스 루트로 옮겨 다운로드 폴더를 깨끗이 한다(6-7 보관 때 `_보관(Archive)`으로 최종 이동).
5. **플랜 B(반드시 내장):** 브라우저가 안 열리거나 5분이 지나도 파일이 안 생기면 — "화면이 불편하시면 여기서 여쭤볼게요"라고 말하고 2-1의 질문을 터미널에서 하나씩 묻는 방식으로 전환한다. 사용자가 위저드를 중간에 닫은 경우도 같다: "다시 열어드릴까요, 아니면 여기서 여쭤볼까요?"

### 2-1. 질문 내용 (위저드 화면에 담을 것)

**질문 ① 워크스페이스 이름 확인**
지금 열려 있는 루트 폴더 이름을 보여주고, 원하면 의미 있는 이름으로 바꿀 수 있다고 알린다. (예: 원작자는 "IRIS"라는 이름을 쓴다.) 바꾸고 싶다면 지금이 마지막 기회임을 알린다 — 나중에 바꾸면 설정이 꼬일 수 있다.

**질문 ② 역할 찾기**
"당신은 삶에서 어떤 역할들을 맡고 계세요?" — 왕초보는 '역할'이라는 말에 막히므로 **반드시 예시 카테고리를 카드로 함께 제시한다**:

- 직업 (교사, 자영업, 회사원, 공무원…)
- 배움 (대학원생, 자격증 준비, 어학…)
- 가정 (부모, 배우자, 자녀 돌봄…)
- 부업·창작 (블로그, 유튜브, 저술, 스마트스토어…)
- 취미·자기관리 (여행, 운동, 재테크…)

역할 개수에 제한은 없다. 사용자가 고르고 적는 대로 다 받는다.

**질문 ③ 역할별 우선순위**
"이 중에서 클로드의 도움을 가장 많이 받고 싶은 역할부터 순서를 매겨주세요." → 이 순서가 R01, R02… 번호가 된다.

**질문 ④ 역할별로 지금 하는 일 (역할마다 반복)**
우선순위 높은 역할부터: "○○ 역할로서 요즘 실제로 진행 중인 일이나 자주 반복하는 일이 있나요?" → 답변을 아래 2-2 판별법으로 D와 P로 분류한다. **지금 진행 중인 일이 없는 역할은 R 폴더만 만들고 속은 비워둔다.** 판단이 애매한 답은 임의로 정하지 말고, 위저드 회수 후 터미널에서 쉬운 말로 되물어라.

### 2-2. 답변 → 구조 번역 판별법

- **역할(R)**: 명함이나 호칭이 될 수 있는 것. "나는 ○○이다"가 자연스러우면 R.
- **도메인(D)**: 그 역할로서 **계속 반복되는 업무 영역**. 끝나는 날이 없다. (수업, 행정, 연구, 살림, 콘텐츠 제작…)
- **프로젝트(P)**: **시작과 끝이 있는 구체적 일**. "이 일이 끝나는 날이 있나요?"에 "네"면 P. (이번 학기 ○○수업, ○○논문, 이번 여행…)
- **S(단계)·T(세부작업)는 인터뷰에서 만들지 않는다.** 실제 일을 시작할 때 그 프로젝트의 클로드가 만들면 된다. 다만 사용자가 이미 구체적 단계를 말했다면 만들어도 좋다.
- 판단이 애매하면 임의로 정하지 말고 사용자에게 쉬운 말로 되물어라. ("○○는 계속 하시는 일인가요, 아니면 끝나는 날이 있는 일인가요?")

### 2-3. 구조 초안 제시와 승인 — 위저드 2탄 (자동 모드는 이 절 생략)

인터뷰 결과를 2-2로 번역해 전체 폴더 트리를 설계했으면, **두 번째 위저드 `세팅위저드-구조승인.html`** 로 보여준다:

1. 화면 구성: ① 폴더 트리를 색·들여쓰기로 시각화하고 각 폴더 옆에 한 줄 설명(아래 예시의 내용) → ② 항목마다 "이름 바꾸기 / 빼기" 수정칸 → ③ 자유 의견 입력칸 → ④ **"좋아요, 이대로 만들어주세요!"** 큰 버튼.
2. 승인 버튼은 `세팅구조승인-결과.json`(`{"wizard": "structure", "approved": true, "edits": [...]}`)을 다운로드시키고, 너는 2-0과 같은 방식으로 회수한다. 수정 요청이 있으면 반영해 위저드를 다시 띄우고, **사용자가 승인할 때까지 반복한다. 승인 후에만 3부(생성)로 넘어간다.** 확정된 트리를 `세팅진행상황.md`에 기록한다.
3. 플랜 B는 2-0과 동일 — 위저드가 안 되면 터미널에 텍스트 트리를 그려 보여주고 문답으로 승인받는다.

트리 표기 예시(위저드 화면·터미널 공통):

```
📁 MYSPACE (워크스페이스 루트)
├─ 📁 R01-학원장(Academy Director)   ← 본업
│   └─ 📁 D01-수업운영(Class Management)
│       └─ 📁 P01-여름특강(Summer Intensive) 〖2026년〗  ← 8월에 끝나는 일
├─ 📁 R02-부모(Parent)               ← 지금 진행 중인 일 없음, 자리만
└─ 📁 R03-블로거(Blogger)
    └─ 📁 D01-콘텐츠(Content)
```

## 3부. 구조 생성

승인된(자동 모드: 설계된) 트리를 아래 순서로 만든다. **폴더 생성은 전부 네가 직접 한다** (사용자에게 손으로 만들라고 시키지 마라 — 특수문자 `〖 〗` 때문에 실수하기 쉽다).

### 3-1. 루트 AGENTS.md 작성 (가장 먼저)

**부록 A의 루트 AGENTS.md 템플릿**을 가져와서:

1. `{{워크스페이스이름}}` 등 자리표시자를 인터뷰 결과로 채운다.
2. 인터뷰 중 사용자가 말한 **그 사람 고유의 전역 규칙**이 있으면 추가한다. (예: "모든 문서는 존댓말로", "우리 학교 이름은 ○○") 단, 특정 역할에만 해당하는 규칙은 루트가 아니라 그 R 폴더 AGENTS.md로 보낸다 — 무중복 원칙.
3. 함께 모드: 완성본을 사용자에게 보여주고 쉽게 요약 설명한 뒤 승인받는다. ("이건 모든 대화에 적용될 기본 규칙이에요. 나중에 언제든 바꿀 수 있어요.")

### 3-2. 폴더 + 미니멀 AGENTS.md 생성

트리대로 R/D/P 폴더를 만들면서, **모든 폴더에 부록 B 템플릿으로 초미니멀 AGENTS.md + CLAUDE.md 껍데기(`@AGENTS.md` 한 줄)를 함께 만든다**:

- **R 폴더**: 인터뷰에서 파악한 그 역할의 1~2줄 정체성을 적는다. (예: "이 폴더의 나는 학원을 운영하는 원장이다. 학부모 응대 문서는 정중하고 신뢰감 있게 쓴다.") 심화 페르소나는 세팅 때 만들지 않는다 — 6-6 확장 안내로 미룬다.
- **D 폴더**: 그 업무 영역이 무엇인지 1줄. (예: "수업 운영 관련 모든 작업을 다루는 도메인.")
- **P 폴더**: 그 프로젝트가 무엇이고 언제 끝나는지 1줄.
- 모든 미니멀 AGENTS.md 끝에는 무중복 가드 주석을 넣는다: `<!-- 상위 AGENTS.md 규칙을 여기 재서술하지 말 것 -->`

### 3-3. 생성 결과 확인

1. 만들어진 실제 폴더 트리를 다시 보여주고 트리와 같은지 확인한다.
2. 사용자에게 **직접 눈으로 보는 법**을 알려준다: "파일 탐색기(윈도우의 폴더 보는 프로그램)에서 ○○ 폴더를 열어보세요. 방금 만든 폴더들이 보일 거예요."
3. 한 가지를 예고한다: "앞으로 ○○ 일을 할 때는 그 프로젝트 폴더에서 클로드를 열면, 클로드가 그 일의 맥락을 자동으로 알아요." (여는 법은 6부에서 실습)
4. `세팅진행상황.md`에 3부 완료를 기록한다.

**금지사항:** 이 단계에서 `git init`을 하지 마라 (1-4 참조). 사용자의 기존 파일이 루트 폴더에 이미 있다면 옮기거나 지우지 말고 그대로 두고, 구조와 섞여 헷갈리면 사용자에게 알리기만 하라.

## 4부. 기반 환경 세팅

### 4-1. 기반 프로그램 3종 설치 (필수, 일괄)

아래 3개는 **필수**다. 설치돼 있는지 직접 확인하고(`git --version`, `node --version`, `python --version`), 없는 것은 모두 설치한다:

| 프로그램 | 사용자에게 설명할 말 | 설치 명령 |
|---|---|---|
| git (깃) | "도구들을 인터넷에서 내려받을 때 쓰는 운반 프로그램" | `winget install Git.Git` |
| Node.js (노드) | "많은 클로드 확장 도구가 돌아가는 데 필요한 엔진 ①" | `winget install OpenJS.NodeJS.LTS` |
| Python (파이썬) | "확장 도구 엔진 ②" | `winget install Python.Python.3.12` |

진행 방식:

- 설치 전에 **무엇을 왜 설치하는지 위의 쉬운 설명으로 알리고, 전부 무료임을 밝힌다.**
- winget(윈도우 내장 앱 설치 도구)이 없거나 실패하면, 공식 사이트 다운로드로 대체 안내한다.
- **중요 — 설치 직후 함정:** 방금 설치한 프로그램은 지금 열려 있는 터미널에서 인식되지 않을 수 있다(경로 등록이 새 창부터 적용됨). 설치 후 인식이 안 되면 **오류를 파헤치지 말고**, `세팅진행상황.md`에 현재 위치를 기록한 뒤 사용자에게 이렇게 안내하라: "프로그램 설치를 컴퓨터에 반영하려면 클로드코드를 한 번 껐다 켜야 해요. 창을 닫고 다시 연 다음, 저에게 '세팅 이어서 해줘'라고 말씀해주세요." (0-1을 영구 설정했으므로 재시작해도 bypass 모드는 유지된다 — 혹시 허락 창이 다시 보이면 0-1을 재확인)

### 4-2. 시크릿 금고 만들기

API 키(외부 서비스를 이용할 때 쓰는 비밀번호 같은 인증 문자열)를 한 곳에서만 관리하는 체계를 만든다:

1. `~/.claude/secrets/` 폴더를 만들고, 그 안에 `.env` 파일(부록 C-1)과 `load-keys.ps1`(부록 C-2)을 만든다.
2. 사용자에게 설명: "API 키라는 비밀번호 같은 걸 나중에 쓰게 될 수 있는데, 그걸 보관할 금고를 미리 만들어뒀어요. 지금 넣을 건 없어요."
3. 루트 AGENTS.md 템플릿(부록 A)에는 이미 시크릿 규칙이 들어 있다 — 별도 작업 불필요. (나중에 키가 필요한 MCP를 설치하게 되면 부록 C-3의 런처 패턴을 쓴다 — 세팅 단계에서는 해당 없음.)

### 4-3. 자동 메모리 안내 (설치 아님, 설명만)

사용자에게 한 가지만 알려준다: "클로드는 **폴더마다 따로** 기억 수첩을 만들어요. 교사 폴더에서 나눈 이야기는 교사 폴더에서 기억되고, 다른 폴더에는 안 섞여요. 그래서 **일은 꼭 그 일의 폴더에서 여는 게** 중요해요."
(너 자신을 위한 참고: 그래서 전역 규칙은 메모리에 의존하지 말고 반드시 AGENTS.md에 두는 것이다.)

### 4-4. 이동식 두뇌 만들기 (전원 적용)

클로드의 기억·설정·로그인 — 말하자면 **두뇌**는 원래 컴퓨터 깊숙한 곳(`~/.claude`)에 저장된다. 그래서 워크스페이스 폴더를 통째로 복사해 다른 컴퓨터로 옮겨도 몸(폴더)만 가고 두뇌는 남는다. 이 절에서 두뇌를 워크스페이스 안으로 이사시켜 **"폴더 하나 = 나의 에이전트 전부"** 를 만든다(원작자 실사용 검증 구조). 사용자에게는 달팽이 비유로 설명하라: "클로드가 집(기억·설정)을 등에 지고 다니게 만들 거예요. 그러면 이 폴더만 복사하면 어떤 컴퓨터에서든 내 클로드가 그대로 살아나요."

절차(전부 네가 직접 한다):

1. 워크스페이스 루트에 `_agent\claude` 폴더를 만들고(`_agent`에 미니멀 AGENTS.md 세트: "AI 에이전트 두뇌 보관소. 사용자가 직접 건드릴 일 없음"), 기존 `~/.claude`의 내용을 그 안으로 **복사**한다(이동 아님 — 원본은 보험으로 남긴다). 단 **`secrets` 폴더는 복사하지 않는다** — API 키 금고는 일부러 컴퓨터에 남긴다. 폴더가 USB로 복사돼 돌아다녀도 비밀번호(키)는 따라다니지 않게 하는 보안 설계다(부록 C의 경로는 그대로 유효).
2. 사용자 환경변수 `CLAUDE_CONFIG_DIR`(클로드에게 "두뇌는 여기 있다"라고 알려주는 주소표)을 새 위치로 **영구 등록**한다:
   `[Environment]::SetEnvironmentVariable("CLAUDE_CONFIG_DIR", "<루트>\_agent\claude", "User")`
3. 루트에 `소환.ps1`을 만든다 — **부록 F의 원작자 검증본 템플릿**을 그대로 쓰되 워크스페이스 이름만 채운다. 이 스크립트는 실행될 때마다 주소표를 재등록하고 워크스페이스 폴더에서 클로드를 켜준다.
4. 재시작한다 — 환경변수는 새 창부터 적용되므로 4-1의 함정과 같은 요령으로: `세팅진행상황.md`에 현재 위치를 기록하고 "클로드코드를 끈 다음, 이번에는 `소환.ps1` 파일을 우클릭 → PowerShell로 실행으로 켜주세요. 그리고 '세팅 이어서 해줘'라고 말해주세요."라고 안내한다.
5. 재시작 후 검증: `$env:CLAUDE_CONFIG_DIR`이 새 위치를 가리키는지, 이전 대화 기억이 유지되는지 확인한다. **이후 이 가이드의 "사용자 전역(`~/.claude/`)" 표기는 전부 이 이동식 두뇌(`_agent\claude`)를 뜻한다**(시크릿 금고 `~/.claude/secrets`만 예외 — 진짜 `~/.claude`에 남는다).

알아둘 것: 나중에 클로드가 기억을 잃은 것처럼 보이면 십중팔구 주소표(환경변수)가 지워진 것이다 — **`소환.ps1`을 다시 실행하면 복구된다**(6-5 사용설명서에 이 만능 버튼을 명시하라). 이 절을 5부(도구 설치)보다 먼저 하는 이유: 도구 등록 정보가 두뇌에 기록되므로, 이사 후에 설치해야 새 두뇌에 바로 적힌다.

완료 후 `세팅진행상황.md`에 4부 완료(이동식 두뇌 포함)를 기록한다.

### 5-3. 브라우저 자동화 — Playwright MCP

클로드에게 **손**을 달아주는 도구다. 지금까지는 "○○ 사이트에서 △△ 찾아줘"에 말로만 안내할 수 있었다면, 이걸 붙이면 클로드가 브라우저를 대신 열고 클릭·입력·읽기를 해서 결과를 가져온다. 사용자에게: "제가 직접 인터넷 화면을 열고 눌러보면서 심부름할 수 있게 해주는 도구예요."

설치(네가 직접, 한 줄):

```
claude mcp add playwright --scope user -- npx -y "@playwright/mcp@latest"
```

- 마이크로소프트 공식 도구로 무료이며 API 키가 필요 없다. 노드(4-1)를 쓰므로 전제조건도 이미 갖춰져 있다.
- **첫 사용 때 전용 브라우저 엔진을 자동 다운로드한다(1~2분)** — 처음 브라우저 심부름을 시켰을 때 잠깐 걸리는 것이 정상이라고 안내하라.
- (참고: 클로드코드에는 크롬 확장을 쓰는 네이티브 브라우저 연동도 있지만, 크롬 설치·확장 로그인 등 왕초보 진입 단계가 늘어나 이 가이드는 Playwright를 표준으로 한다.)
- **안전 규칙**: 로그인·결제·제출·예약처럼 되돌리기 어려운 버튼은 누르기 전에 반드시 사용자 확인 — 부록 A 템플릿에 이 규칙이 들어 있다.
- 등록 후 동작 확인: 아무 공개 페이지 하나를 열어 제목을 읽어오게 해본다. 회사 보안 프로그램 등이 자동 브라우저를 막는 환경이면 5-0 예외 처리(건너뛰고 기록)로 흡수한다.

### 5-4. 한국 생활 스킬팩 — k-skill 114종

한국 실생활 조회·작업 스킬 모음이다: 택배 배송 조회, 날씨·미세먼지, 학교 급식, KTX/SRT 예매 보조, 법령·판례 검색, 부동산 실거래가, 지역 검색, 맞춤법 검사 등 114개. 사용자에게: "한국에서 사는 데 필요한 잔심부름 기술 모음이에요. 택배 조회, 날씨, 기차표 알아보기 같은 걸 바로 시킬 수 있게 돼요."

설치 절차:

1. **이것은 플러그인이 아니다** — `/plugin` 명령이 아니라 터미널 명령으로 설치하며, **네가 직접 실행한다**:
   ```
   npx --yes skills add NomaDamas/k-skill --all -g
   ```
   (`-g` = 사용자 전역 설치. 저장소 README에 다른 설치법이 안내돼 있어도 이 명령이 정식 경로다.)
2. 설치 결과를 확인한다: `~/.claude/skills/` 안에 스킬 폴더들이 생겼는지 본다.
3. **다음 재시작부터 로드된다** — 지금 당장 6-1 검증에서 개수만 확인하고, 동작 확인은 6-4 졸업 시험 후에 아무 스킬 하나(예: 날씨)로 해본다.

알아둘 것:

- 토큰 비용: 상시 로드되는 것은 각 스킬의 이름+한 줄 설명뿐(세션당 약 13k 토큰). 본문은 쓸 때만 로드된다(점진적 공개). 5-5의 지연 로딩과 함께 쓰면 부담이 크지 않다.
- 상당수 스킬은 **첫 사용 시 무료 API 키 발급이 필요**할 수 있다 — 그 순간에 `k-skill-setup` 스킬이 안내한다. 세팅 단계에서 미리 키를 받을 필요 없다.
- 예약·결제·자동화 계열 스킬은 실행 전에 반드시 사용자에게 내용을 확인받아라.
- 나중에 안 쓰는 스킬 정리는 `k-skill-cleaner` 스킬로 할 수 있다 (6-6 확장 안내에 포함).

완료 후 `세팅진행상황.md`에 5-4 완료를 기록한다.

### 5-5. 토큰 효율 설정 — MCP 지연 로딩 켜기 (필수)

도구 설치가 끝났으면 마지막으로 설정 하나를 추가한다. MCP를 여러 개 설치하면 **매 대화 시작마다 모든 도구의 상세 설명서가 클로드의 작업 기억(컨텍스트)에 통째로 실려** 토큰이 낭비되고, 무관한 도구가 많을수록 도구 선택 정확도도 떨어진다. 클로드코드의 **지연 로딩(Tool Search, 도구 설명서를 미리 다 싣지 않고 필요할 때 찾아 읽는 기능)** 을 켜면 두 문제가 함께 해결된다 — Anthropic 실측 기준 도구 정의 토큰 약 85% 절감 + 도구 선택 정확도 상승(성능 손해 없음).

자동 발동 조건(도구 정의가 가용 컨텍스트의 10% 초과)은 도구 수십 개 규모에서는 대개 충족되지 않으므로 **반드시 명시적으로 켠다**:

1. `~/.claude/settings.json` 파일을 연다 (없으면 만든다).
2. `env` 항목에 `"ENABLE_TOOL_SEARCH": "true"` 한 줄을 추가한다. 파일이 비어 있었다면 전체는 이렇게 된다:

   ```json
   {
     "env": {
       "ENABLE_TOOL_SEARCH": "true"
     }
   }
   ```

   기존 내용이 있으면 JSON(중괄호·따옴표 형식의 설정 파일)이 깨지지 않게 `env` 안에 한 줄만 추가한다.
3. 사용자에게 설명: "클로드가 도구 설명서를 미리 다 외워두는 대신 필요할 때만 꺼내 읽게 하는 절약 설정이에요. 대화 용량을 아끼면서 도구는 오히려 더 정확하게 골라요."
4. 이 설정은 **다음에 클로드코드를 새로 열 때부터** 적용된다.

완료 후 `세팅진행상황.md`에 5-5 완료를 기록한다.

### 6-2. 구조지도 — 자동 생성 스크립트 만들기

전체 폴더 구조를 한눈에 보는 지도를 만든다. **HTML을 직접 손으로 만들지 마라** — 원작자가 그렇게 하다가 폴더 구조와 지도가 어긋나는 문제(드리프트)로 폐기한 방식이다. 대신 **폴더를 스캔해서 지도를 그려주는 스크립트**를 만든다:

1. 루트에 `_map-generator` 폴더를 만든다 (미니멀 AGENTS.md 포함: "구조지도 생성 스크립트 보관소").
2. 그 안에 `build_map.py`를 작성한다. 요구 사양:
   - 워크스페이스 루트의 R/D/P/S/T 폴더 트리를 스캔한다 (`_` 폴더·숨김 폴더는 제외하되 이름 규칙에 맞는 것만).
   - 각 폴더의 AGENTS.md 첫 정체성 줄을 읽어 한 줄 설명으로 표시한다.
   - `{{워크스페이스이름}}-구조지도.html`을 루트에 생성한다 — 더블클릭하면 브라우저에서 열리고, ① 역할별 색상 구분 ② R→D→P 트리 시각화 ③ 폴더별 한 줄 설명 ④ 컴퓨터 지식 없이 이해 가능할 것. (도메인 그룹 접두 `〖그룹〗`이 있으면 가상 묶음 노드로 표시.)
   - 재실행하면 항상 현재 폴더 구조를 새로 그린다 (덮어쓰기).
3. 스크립트를 한 번 실행해 지도를 생성하고, 사용자에게 여는 법을 알려주고 함께 열어본다.
4. 규칙: **구조지도 HTML은 절대 손으로 편집하지 않는다.** 폴더 구조가 바뀌면 스크립트를 다시 실행해 재생성한다. (이 규칙은 부록 A 템플릿에 들어 있다.)

### 6-3. 훈장 달기 — 워크스페이스 전용 아이콘

구조와 지도가 완성된 지금이 가장 뿌듯한 순간이다 — 마무리로 워크스페이스 폴더에 **전용 아이콘(폴더 겉에 씌우는 그림 옷)** 을 달아준다. 수십 개 폴더 사이에서 내 워크스페이스가 한눈에 띄게 된다. 사용자에게: "폴더에 훈장을 하나 달아드릴게요. 마음에 드는 걸 골라만 주세요."

1. **후보 100종 생성(무료·오프라인·키 불필요):** 파이썬 그림 라이브러리 Pillow(필로우 — 코드로 도형을 그리는 도구. `pip install pillow`)로 **무늬 10종 × 색깔 10종 = 100종** 후보를 그린다. AI 그림 생성이 아니라 도형 그리기라서 비용이 전혀 없다.
   - 무늬 10종: 그라데이션 / 별밭 / 링 / 산 능선 / 파도 / 도트 / 스트라이프 / 선버스트 / 벌집 / 초승달
   - 색깔 10종: 우주(남보라) / 바다(파랑) / 보라 / 노을(자홍-주황) / 숲(초록) / 청록 / 골드(검정+금) / 벚꽃(분홍) / 태양(빨강-주황) / 잿빛(회청)
   - 각 후보는 512픽셀, 모서리 둥근 사각형, **글자 없이 무늬만**. 100개를 **행=무늬, 열=색깔** 격자 한 장(전체보기 시트)으로 합치고 각 칸 아래 번호(1~100)를 크게 단다. 제목: "마음에 드는 번호 하나만 말씀하세요 (안 할래요도 괜찮아요)".
2. 전체보기 시트를 브라우저로 띄우고 **번호 하나만** 답하게 한다. **"안 할래요"면 이 절을 통째로 건너뛴다**(`세팅진행상황.md`에 기록만). "○○색으로 다시 보여줘"라고 하면 그 색 계열로 후보를 다시 그려준다.
3. 선택되면 적용한다(전부 네가 직접): 선택 후보를 다중 해상도 `.ico`(256/48/32/16픽셀 — 큰 화면·작은 목록 어디서든 선명)로 변환해 루트에 `_아이콘.ico`로 저장 → 루트에 `desktop.ini`를 만들어 `IconResource=<루트>\_아이콘.ico,0` 지정 → `desktop.ini`에 숨김+시스템 속성, 루트 폴더에 읽기 전용 속성 부여(윈도우가 "꾸며진 폴더"로 인식하는 스위치) → 후보 생성용 임시 파일 정리.
4. 사용자에게 확인시킨다: "파일 탐색기에서 상위 폴더로 나갔다 들어와 보세요." **바로 안 보여도 고장이 아니다** — 윈도우가 아이콘을 캐시(한 번 본 그림을 기억해두는 임시 저장소)해서 늦게 반영되기도 한다. "다음에 컴퓨터를 껐다 켜면 나타나요, 정상이에요"라고 안심시켜라.
5. 참고: `desktop.ini`는 숨김 파일이라 구조지도 스캔(6-2 사양의 숨김 제외)에 잡히지 않는다. 나중에 그림 생성 도구(유료 API)를 연결하면 더 화려한 아이콘으로 갈아입힐 수 있다(6-6 확장 안내).

### 6-4. 사용법 교육 — "딱 한 가지만 기억하세요"

사용자에게 핵심 습관 하나를 실습으로 가르친다: **"일은 그 일의 폴더에서 연다."**

1. 여는 법을 단계별로 가르친다: "파일 탐색기에서 일할 폴더를 연다 → 위쪽 주소창을 클릭하고 `cmd`라고 입력 후 엔터 → 까만 창이 뜨면 `claude` 입력 후 엔터."
2. **졸업 시험(실습):** 사용자에게 지금 클로드코드를 끄고, R01 역할 폴더에서 새로 열어서 아무 인사나 해보라고 한다. 새 클로드가 그 역할의 맥락을 아는 채로 대답하면 세팅 성공을 눈으로 확인하는 것이다. (이 재시작으로 k-skill·지연 로딩 설정도 함께 반영된다 — 이때 날씨 등 스킬 하나를 시켜보면 5-3 동작 확인까지 끝난다.)

### 6-5. 개인 사용설명서 만들기

워크스페이스 루트에 `사용설명서.md`를 만든다 — 이번엔 **사람이 읽는 문서**다. 내용:

1. 내 폴더 구조 한눈 요약
2. 폴더에서 클로드 여는 법 (6-4의 3단계)
3. 자주 하는 일 예시 3~5개 — 인터뷰 내용 기반 맞춤 (예: "여름특강 자료 만들기 → R01/D01/P01 폴더에서 열고 말하세요")
4. 새 프로젝트를 시작할 때: 그냥 클로드에게 "○○ 프로젝트 시작할래"라고 말하면 폴더를 만들어준다
5. 곤란할 때: 뭐든 클로드에게 물어보면 된다
6. **컴퓨터를 바꾸면**: 워크스페이스 폴더를 통째로 복사한 뒤, 새 컴퓨터에서 `소환.ps1` 우클릭 → PowerShell로 실행 — 그걸로 끝. **클로드가 기억을 잃은 것 같을 때도 `소환.ps1` 재실행이 만능 복구 버튼**이다 (4-4)
7. 브라우저 심부름 예시 1개 (5-3 기반, 인터뷰 내용 맞춤 — 예: "○○ 사이트에서 △△ 알아봐줘")

### 6-6. 확장 안내 (사용설명서에 포함할 것)

- **역할 페르소나 심화**: 어떤 역할 폴더에서 클로드에게 "내 말투와 스타일을 반영해줘"라고 하면 그 역할의 AGENTS.md가 풍부해진다.
- **규칙 추가**: "앞으로 항상 ○○해줘"라고 말하면 클로드가 알맞은 레벨의 AGENTS.md에 적어준다.
- **도구 추가**: 그림 생성, 지메일 연동 등은 필요해지는 순간 클로드에게 말하면 된다 (비용이 드는 것은 클로드가 먼저 알려준다 — 부록 A의 API 키 원칙). 특정 역할에서만 쓰는 도구는 그 역할 폴더에만 설치할 수도 있다 (1-4 스코핑 — 클로드가 판단해준다).
- **스킬 정리**: 한국 생활 스킬팩 중 안 쓰는 것은 "안 쓰는 스킬 정리해줘"라고 하면 된다 (`k-skill-cleaner`).

### 6-7. 종료

1. `세팅진행상황.md`에 전체 완료를 기록한다.
2. 워크스페이스 루트에 `_보관(Archive)` 폴더를 만들고(미니멀 AGENTS.md 포함), **이 세팅가이드 파일과 `세팅진행상황.md`, 위저드 HTML·결과 JSON 파일들을 그 안으로 이동**한다. 사용자에게 "세팅에 쓴 문서들은 보관함에 넣어뒀어요"라고 알린다.
3. 권한 영구 설정(0-1)을 한 줄로 고지한다: "참고로, 클로드가 매번 허락을 묻지 않고 일하도록 설정해뒀어요. 언제든 '허락 창 다시 켜줘'라고 하시면 되돌려드려요."
4. 축하 인사와 함께 첫 실전 과제를 하나 권한다: "지금 가장 급한 일 하나를 말씀해보세요. 바로 도와드릴게요."

````markdown
## 사용자 응대 원칙 (최우선)

사용자는 컴퓨터 비전문가다. 모든 대화에서:
- 전문용어·영어 약어는 처음 나올 때 쉬운 말로 풀이한다.
- 선택지를 줄 때는 항상 추천 기본값을 함께 준다.
- 실행하면 결과물이 남는 일은 하기 전에 "지금부터 ○○할게요"라고 예고하고, 끝나면 무엇이
  만들어졌는지 알려준다.
- 오류가 나면 사용자를 안심시키고 대안을 시도한다. 화면의 영어 메시지는 한국어로 요약해준다.
- 사용자의 파일을 지우거나 덮어쓰기 전에는 반드시 확인받는다.
- 브라우저 자동화 등으로 **로그인·결제·제출·예약처럼 되돌리기 어려운 버튼**을 누르기 전에는
  반드시 사용자에게 확인받는다.

## 쉬운 설명 원칙 (Easy-Explain)

무언가를 **설명**할 때(개념 해설·상황/결과 보고·기술적 사건 요약 등)는 아래 방식을 기본으로 한다:

- **서사 순서로 전개**: ① 우리가 필요한 것/목표 → ② 지금 가진 것/현재 상태 → ③ 문제 또는 결과
  → ④ 그래서 무슨 의미인가 → ⑤ 남은 결정/다음 행동. 결론만 던지지 말고 맥락부터 차례로 쌓는다.
- 문장은 짧게, 한 문장에 한 생각.
- **생활 비유를 적극 사용**: 핵심 개념마다 일상 비유를 붙이고(예: 자동 밝기 보정=폰 카메라,
  재보정=저울 영점), 가능하면 하나의 관통 비유로 전체를 마무리 요약한다.
- **숫자는 해석과 함께**: "240초에 6.5도 하락 = 1분에 1.65도"처럼 값 옆에 항상 의미를 병기한다.
- **안심 구조**: 나쁜 소식 뒤에는 반드시 "그래서 망했나? → 아니다, 살아 있는 것"을 짚어 균형을 잡는다.
- **마무리 재요약**: 맨 끝에 전체를 한 문장(또는 관통 비유 한 문단)으로 다시 접는다.

## 설계 우선 원칙 (Design-First)

실질적 작업(파일 생성·대량 수정·자동화 실행 등 결과물이 남는 일) 직전에는 항상 먼저 설계한다.
설계의 최종 점검은: ① 조각으로 분리 ② 첫 조각부터 하나씩 ③ 왕초보 눈높이로 설명(전문용어는
첫 등장 시 풀이) ④ 빈틈·개선안 함께 제안 ⑤ 피드백 받아 수정 ⑥ 전 조각 확정까지 반복.
이 점검 전에는 실행에 들어가지 않는다. (단순 질문 답변·파일 열람은 제외.)

## 논리 흐름 뷰 (Logic-Flow View)

사용자가 글·발표·계획의 **논리 흐름을 보고 싶다/짜고 싶다**고 하면, 제작 디테일은 걷어내고
**논리 뼈대만** 짧은 핵심 문장의 연속으로 제시한다:
- 한 문장 = 한 줄로 세로 나열. 앞 문장 → 뒤 문장의 이행이 논리적으로 타당해야 한다(핵심 검토 대상).
- 맨 위에 〈한눈에〉: 전체 층위 구조 + 관통하는 핵심 주제.
- 단위(장·절)별로: 여는 전제 → 전개 핵심 → **착지**(한 문장, 굵게) → 다음 단위로의 연결(브리지, `↳` 표시).
- 맨 끝에 〈연결 장치〉: 복선↔회수, 수미상관 등 흐름을 묶는 반복 장치 요약.
- 목적 = 사용자가 이음매를 한 줄씩 검토·수정하게 하는 것.

## 폴더 계층 ({{워크스페이스이름}} → Role → Domain → Project → Step → Task)

- Role: `R0X-한글(영어)` / Domain: `D0X-한글(영어)` / Project: `P0X-한글(영어)`
  / Step: `S0X-한글(영어)` — 일 진행 순서대로 번호 / Task: `T0X-한글(영어)` — 필요할 때만.
- 5계층은 고정이다. 역할이 하나뿐이어도 R01부터 시작하며 계층을 생략하지 않는다.
- 괄호 앞에 공백 없음. 폴더는 요청이 있을 때만, 필요한 것만 생성.
- **모든 폴더는 AGENTS.md + CLAUDE.md 껍데기(`@AGENTS.md` 한 줄)를 갖는다.** 폴더를 만들 때
  그 폴더의 초미니멀 AGENTS.md(1줄 정체성 + 무중복 가드 주석)와 껍데기를 항상 함께 만든다.
- 코드가 안 어울리는 공용 폴더는 `_` 접두를 쓴다 (예: `_도구(Tools)`, `_보관(Archive)`).
- **도메인 그룹 접두(D 전용, 드물게):** 같은 레벨의 D 여러 개가 하나의 상위 묶음에 속하면
  그룹 폴더를 만들지 않고 D 코드 앞에 `〖그룹명〗 `을 붙여 표현한다
  (예: `〖교재〗 D05-전문 물리학(Expert Physics)`). 그룹 안에서 D 번호는 새로 시작한다.
- **미세 하위 표기 `.NN`(위계 예외, 드물게):** 5계층에 딱 안 맞는 '큰 것 안의 작은 것'은
  부모 코드 뒤에 `.NN`(00부터 두 자리)을 붙여 부모와 같은 레벨(형제)로 나란히 둔다
  (예: `D02.00-…`, `D02.01-…`). 물리적으로 형제라 부모의 AGENTS.md는 상속되지 않는다.
  표준 위계로 표현되면 그걸 우선한다.
- 구조 시각화 지도 = 루트 `{{워크스페이스이름}}-구조지도.html`. 폴더 구조가 바뀌면 생성
  스크립트(`_map-generator/build_map.py`)를 실행해 재생성한다 — **지도 HTML은 손으로
  편집하지 않는다**(폴더 스캔으로 자동 생성).

### 표기 기호 규칙

- `-` = 코드↔이름 구분 / `( )` = 영문 표기 / `〖 〗` = 반전각 태그(구별이 필요할 때만).
- `〖 〗`는 아래 닫힌 목록의 용도로만 쓴다. 새 용도가 필요하면 먼저 이 목록에 추가한 뒤 쓴다:
  - 기간/연도 (Project) — `〖YYYY년.N학기〗`, `〖YYYY년〗`
  - 도메인 그룹 접두 (Domain — 유일하게 코드 앞에 붙는 태그) — 위 폴더 계층 항목 참조
  {{인터뷰에서 나온 이 사용자의 태그 용도들 — 없으면 이 줄 삭제}}
- 대괄호 `[ ]`·중괄호 `{ }`는 오작동 위험이 있어 폴더명에 쓰지 않는다.

## 스코핑 규칙

- 디렉터리 트리를 따라 자동 상속되는 것은 AGENTS.md뿐이다.

- 도구 스코프 판단: **쓰는 곳이 고정이면 그 폴더 스코프, 예측 불가하면 사용자 전역 +
  지연 로딩(`ENABLE_TOOL_SEARCH=true`).** 한 역할에서만 쓰는 도구는 그 R 폴더에
  project 스코프로 설치한다(첫 실행 시 승인 1회는 정상).
- **대형 툴셋(툴 수십~백 개)은 MCP 등록 대신 스킬/CLI 형태를 우선 검토한다** — MCP는
  설명서가 상시 토큰을 차지하지만 스킬/CLI는 쓸 때만 로드된다.
- 도구를 새로 조사·설치·제거하면 루트 `{{워크스페이스이름}}-도구조사.md` 한 파일에
  결정 목록과 갱신 로그를 이어 쓴다(단일 원본).
- 기능이 겹치는 도구가 생기면 **기존 MCP·플러그인이 나중에 설치한 스킬보다 우선**한다.
  겹침이 확인되면 이 AGENTS.md에 우선순위를 명시한다.
- 전역 규칙을 자동메모리에 의존하지 않는다 — 반드시 AGENTS.md에 둔다.
- 워크스페이스 안에서 git init은 프로젝트 경계를 바꾸므로 꼭 필요할 때만, 사용자와 상의 후 쓴다.

## API 키 / 시크릿 관리

- 모든 API 키는 `~/.claude/secrets/.env` 한 곳에서만 관리한다 (`KEY=VALUE`).
- AGENTS.md·코드·로그에 키 원문을 절대 넣지 않는다.
- 세션에서 키 로드: `. "$env:USERPROFILE\.claude\secrets\load-keys.ps1"`
- 키가 필요한 MCP를 등록할 때는 키를 설정 파일에 넣지 말고, `~/.claude/tools/<이름>.cmd`
  런처가 `.env`에서 읽어 주입하게 한다 (세팅가이드 부록 C-3 패턴).
- **키가 필요한 기능(이미지 생성, 외부 서비스 연동 등)이 처음 등장하면:**
  ① 그 기능이 무엇인지 쉽게 설명하고 ② 비용이 드는지, 대략 얼마인지 반드시 알리고
  ③ 사용자가 동의한 경우에만 ④ 발급 절차를 한 단계씩 친절하게 안내한다.
  동의 없이 유료 기능을 활성화하지 않는다.
````

## 부록 C. 시크릿 금고 부품

### C-1. `~/.claude/secrets/.env` 초기 내용

```
# 이 파일은 API 키 보관 금고입니다. 한 줄에 하나씩 KEY=VALUE 형식으로 적습니다.
# 이 파일을 절대 다른 곳에 복사하거나 남에게 보내지 마세요.
# (아직 보관된 키 없음 — 필요할 때 클로드가 추가를 도와줍니다)
```

### C-2. `~/.claude/secrets/load-keys.ps1` (원작자 검증본 그대로)

```powershell
# load-keys.ps1 — secrets/.env 의 KEY=VALUE 들을 현재 세션 환경변수로 올린다.
# 사용: . "$env:USERPROFILE\.claude\secrets\load-keys.ps1"  (앞의 점 = dot-source)

$envFile = Join-Path $env:USERPROFILE ".claude\secrets\.env"
if (-not (Test-Path $envFile)) {
    Write-Error "secrets/.env 가 없습니다: $envFile"
    return
}

Get-Content $envFile | ForEach-Object {
    $line = $_.Trim()
    if ($line -eq "" -or $line.StartsWith("#")) { return }
    $k, $v = $line -split "=", 2
    if ($k -and $v) {
        $name = $k.Trim()
        $val  = $v.Trim()
        Set-Item -Path "env:$name" -Value $val
        if ($val -like "REPLACE_WITH_*") {
            Write-Warning "$name 가 아직 플레이스홀더입니다. secrets/.env 에 실제 키를 넣으세요."
        }
    }
}
```

### C-3. 키 주입 런처 패턴 (세팅 후, 키가 필요한 MCP를 추가할 때)

MCP가 API 키를 요구할 때, 키를 클로드코드 설정 파일에 직접 적으면 안 된다(설정 파일은
백업·공유 과정에서 노출되기 쉽다). 대신 **런처(launcher, 키를 금고에서 읽어와 도구를 대신
실행해주는 작은 실행 파일)** 를 만들어 등록한다. 원작자 검증 패턴:

1. `~/.claude/tools/` 폴더를 만들고 (없으면), 그 안에 `<도구이름>.cmd`를 만든다:

   ```bat
   @echo off
   rem <도구이름> MCP launcher - 키를 설정 파일이 아닌 secrets .env에서 읽어 주입한다
   for /f "usebackq tokens=1,* delims==" %%a in ("%USERPROFILE%\.claude\secrets\.env") do if /i "%%a"=="<키이름>" set "<키이름>=%%b"
   <실제 MCP 실행 명령>
   ```

   (키가 여러 개면 `for /f ... if /i "%%a"=="..."` 줄을 키마다 반복한다.)
2. 키 자체는 `~/.claude/secrets/.env`에 `<키이름>=값` 한 줄로 추가한다.
3. MCP 등록 시 실행 명령으로 이 `.cmd` 파일을 지정한다. 이렇게 하면 설정 파일에는
   런처 경로만 남고 키 원문은 금고 밖으로 나가지 않는다.

## 부록 E. 다른 AI 에이전트(코덱스 등)를 나중에 추가할 때

세팅 단계에서는 아무것도 하지 않는다. 이 부록은 나중에 사용자가 코덱스(OpenAI Codex) 등 `AGENTS.md`를 읽는 다른 에이전트를 추가하고 싶다고 할 때, 그때의 클로드가 읽고 실행하는 절차다. (이 워크스페이스의 지침 원본은 이미 AGENTS.md라서 지침을 두 벌 관리할 필요가 없다 — 아래 표지판만 세우면 다른 에이전트가 같은 지침을 즉시 읽는다.)

1. **대가부터 고지하고 동의받는다.** 표지판(아래 2번)을 세우면 클로드코드가 워크스페이스 전체를 하나의 프로젝트로 보게 되어, **폴더마다 따로이던 기억 수첩(4-3)이 워크스페이스 전체 하나로 합쳐진다.** 다른 에이전트를 실제로 쓸 사람에게만 이득이 있는 거래다.
2. **git 표지판 세우기**: 워크스페이스 루트에서 `git init` 실행 후, `.gitignore` 파일에 `*` 한 줄만 넣는다(전부 무시). **커밋은 절대 하지 않는다** — 이 저장소는 기록용이 아니라 "여기부터가 한 단지"라는 표지판일 뿐이다. 코덱스는 이 표지판이 있어야 하위 폴더에서 상위 AGENTS.md를 거슬러 올라가 읽는다.
3. **새 에이전트의 두뇌도 `_agent\<이름>`에 둔다** (예: 코덱스는 환경변수 `CODEX_HOME`을 `<루트>\_agent\codex`로 영구 등록) — 4-4 이동식 두뇌와 같은 사상으로, 폴더 복사만으로 전부 함께 이사되게 한다.
4. ⚠️ **경고 2가지**: ① 표지판 `.git` 폴더를 지우면 다른 에이전트의 상위 지침 상속이 끊긴다(원작자가 실제 겪은 함정 — 지우지 말 것). ② 워크스페이스 안에 나중에 진짜 git 프로젝트(개발 폴더)가 생겨도 안전하다 — git은 가장 가까운 표지판을 경계로 보므로 안쪽 프로젝트가 우선한다.

## 부록 F. 소환.ps1 템플릿 (원작자 검증본 일반화)

4-4에서 워크스페이스 루트에 만든다. `{{워크스페이스이름}}`만 채운다.

```powershell
# ============================================================
#  {{워크스페이스이름}} 소환 스크립트
#  "폴더 하나 = 나의 에이전트 전부" — 이 폴더와 이 스크립트만 있으면
#  어떤 컴퓨터에서든 클로드를 같은 기억·설정으로 소환할 수 있다.
#  사용법:  우클릭 → PowerShell로 실행
# ============================================================

$Root  = Split-Path -Parent $MyInvocation.MyCommand.Path   # 이 스크립트가 있는 폴더 = 워크스페이스 루트
$Brain = Join-Path $Root "_agent\claude"                   # 클로드 두뇌 (기억·스킬·설정·로그인)

# 1) 두뇌 폴더 확인
if (-not (Test-Path (Join-Path $Brain "settings.json"))) {
    Write-Host "[오류] 두뇌 폴더가 없습니다: $Brain" -ForegroundColor Red
    Write-Host "       백업이 있다면 그 안의 _agent\claude 를 이 위치로 복원한 뒤 다시 실행하세요."
    Read-Host  "엔터를 누르면 닫힙니다"
    exit 1
}

# 2) 환경변수 영구 등록 (이 사용자 계정의 모든 새 터미널에 적용)
$current = [Environment]::GetEnvironmentVariable("CLAUDE_CONFIG_DIR", "User")
if ($current -ne $Brain) {
    [Environment]::SetEnvironmentVariable("CLAUDE_CONFIG_DIR", $Brain, "User")
    Write-Host "[설정] CLAUDE_CONFIG_DIR = $Brain (영구 등록됨)" -ForegroundColor Cyan
}
$env:CLAUDE_CONFIG_DIR = $Brain   # 지금 이 창에도 즉시 적용

# 3) 클로드코드 설치 확인
$claudeCmd = Get-Command claude -ErrorAction SilentlyContinue
if (-not $claudeCmd) {
    Write-Host "[안내] 클로드코드가 설치되어 있지 않습니다." -ForegroundColor Yellow
    Write-Host "       설치: https://claude.com/claude-code 참조 후 이 스크립트를 다시 실행하세요."
    Read-Host  "엔터를 누르면 닫힙니다"
    exit 1
}

# 4) 소환
Set-Location $Root
Write-Host ""
Write-Host "  {{워크스페이스이름}} 에이전트를 소환합니다 — 작업 폴더: $Root" -ForegroundColor Green
Write-Host ""
claude
```
